# 0018 从已有分支创建工作树

- 状态：已采用（2026-11）；扩展 [0012](0012-worktrees.md) 的新建工作树流程

## 背景

原来的 New Worktree 对话框只能创建新分支。用户想在另一个目录打开已有本地分支时，必须使用命令行。

## 决定

- 在原对话框内区分新建分支和已有分支，默认仍创建新分支。已有分支模式不提供起点，因为工作树应检出该分支当前的提交。
- 仅支持已有本地分支，不从远端猜测或自动创建分支。已被工作树占用的分支不能重复检出。
- 分支使用对话框内的可滚动列表，显示占用原因，避免既有焦点陷阱阻挡弹出菜单。
- 保留按分支名建议路径的行为，用户手动修改路径后不再覆盖。
- Git 命令层再次验证分支；最终由 `git worktree add` 检查执行时的占用和目标路径。不使用 force 或重置分支的选项。
- 成功后重新读取仓库状态；失败沿用现有错误通知，不修改原工作区的 HEAD、索引或文件。

## 代价与替代项

独立入口会重复路径输入和验证逻辑，因此复用原对话框。前端状态可能因外部 Git 操作而过期，界面通过验证不保证执行成功，仍须保留 Git 的错误信息。

## 复审条件

需要支持 detached worktree、从远端创建跟踪分支或清理失效工作树时，分别明确操作后果和恢复方式，再扩展界面。
