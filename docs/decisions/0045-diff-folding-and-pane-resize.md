# 0045 Diff 折叠未更改片段与可调分栏

- 状态：已采用（2026-11）

## 背景

大文件里只有少量分散改动时，完整 diff 会把大部分屏幕留给未更改的上下文，读者反而要反复滚动才能找到下一处改动；并排视图的左右两栏又固定平分宽度，长行或宽屏下总有一侧不够用。Issue #76 与 #77 分别要求折叠相同片段、调整对比栏宽度。

## 替代项

- **在数据层裁剪 diff**：只保留改动块与少量上下文，需要改动 `domain` 的 diff 结果或重新向 Git 要 diff。行号、块级暂存、改动标记和选中文本都会失去原始坐标，且展开时要重新请求。
- **每次展开都重新加载 diff**：状态简单，但打开大文件时会有可感知的等待，也破坏 `RepoState` 的代次模型（同一份内容被反复准备）。
- **分栏比例写进全局设置**：跨仓库、跨页签共享一个比例，读者在窄窗口调一次会改变所有后续 diff 的默认布局。

## 决定

- diff 的折叠与分栏都只在视图层表达。`diffTab` 保存源坐标的折叠区间（`foldRange`）与展开状态；`foldedLines` 把源行投影为可见行，并排两侧与统一视图各自投影，但共用同一份折叠索引。Git 结果、块坐标、行号与选中文本仍以源坐标为准，`domain` 与 `app` 不需要知道折叠存在。
- 每个改动块保留三行上下文；去掉上下文后至少还能省出两行的区间才折叠。折叠行绘制为可点击、可聚焦的「未更改的 N 行」，点击或 Enter / Space 展开；展开后保持视口顶部对应的源行不变。
- `DiffCollapse` 是全局设置（默认开启），由 diff 工具栏的按钮切换；切换会重建所有已打开 diff 的折叠状态，关闭时完全展开，重新开启时回到全折叠。展开状态属于当前加载，不跨重载保存。
- 分栏比例属于页签（`diffTab.split`，默认 0.5），拖动分隔条、聚焦后按左右方向键或双击复位调整；窗口缩放时按比例重新计算，最小栏宽为 120px 或可用宽度的一半。
- 滚动、改动标记、搜索命中、当前行与文本选择的光标都经过同一投影换算，避免折叠后坐标错位。

## 代价

- 视图层多一层行号投影与二分查找；每次滚动只换算可见行，成本随可见行数而不是文件长度增长。
- 折叠后行号不连续，选中隐藏区间时复制仍会带出源文本；这是刻意保留的「复制看到的文件内容」语义。
- 默认开启折叠改变了升级后大文件 diff 的初始外观，读者需要知道工具栏按钮与折叠行可以还原完整视图。

## 复审条件

- 如果 Viva 提供内建的可折叠列表或虚拟化投影，改用其组件并删除本层换算。
- 如果折叠影响到块级暂存、改动标记或搜索的坐标正确性，以源坐标为准重新核对并补回归测试。
- 如果用户反馈默认折叠不合适，可在设置页增加默认值并在下一个次版本调整。
