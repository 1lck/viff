# 0042 工作树文本文件的应用内编辑

- 状态：已采用（2026-11）

## 背景

[0024](0024-file-browser.md) 把 Project 工具窗口和文件查看器定为只读：用户能按目录找到文件、用 Git 状态着色、看 blame 与历史，但改一行代码仍要切到外部编辑器。Issue #46 明确要求“支持 edit code”；Viva 现在提供原生多行文本输入（`components.Textarea`、`components.CodeEditor`、`text.Editor`），提交信息框与诊断描述框已经在用同一套输入、IME、选区和撤销。

只读查看器本身承载了行号、水平滚动、语法高亮、blame、代码缩略图、搜索和滚动条。直接换成 `CodeEditor` 会丢行号和水平滚动；换成 `CodeDiff` 会变成双栏，且缩略图、blame 与搜索都要另接。因此这次不替换查看器，而是在同一个页签上增加一个显式编辑模式。

## 替代项

- **继续只读，交给外部编辑器**：实现最省，但用户反馈的核心诉求没有解决。
- **嵌入完整 IDE/编辑器组件**：补全、跳转、LSP、多光标、插件都不是 Git 客户端的范围，也会破坏低内存与单进程边界。
- **用 `CodeEditor` 替换文件查看器**：输入现成，但组件不画行号栏，也没有水平滚动；现有查看器的功能会回退。
- **用 `CodeDiff` 做单文件编辑**：行号与水平滚动齐全，但固定双栏；对“改一个文件”来说一半宽度被同一份内容占掉。
- **允许编辑历史版本、diff 与冲突**：历史版本没有可写目标，diff 的保存目标需要另立模型；冲突文件应先走已有的逐块解决流程，而不是在编辑器里手改标记。

## 决定

- **显式模式，默认不进入**：工作树里的纯文本文件在文件查看器工具栏显示 `Edit`（⌘E），进入后同一页签变成编辑器；`Done` 返回只读查看器。历史版本、图片、二进制、子模块、符号链接、冲突文件和非 UTF-8 文件不显示入口。
- **保留现有渲染与交互**：编辑模式沿用查看器的行号栏、水平滚动、语法高亮和明暗主题，只把文字与光标换成可编辑状态。选区、输入法、剪贴板、撤销/重做由 Viva 的原生文本服务负责；视图通过 `ui.TextPlacement` 告诉运行时按哪里落光标、输入法窗口放哪里。
- **保存走应用层**：新增 `Workspace.SaveFile`，作为写任务与同一仓库的 Git 写操作串行。写之前重新读取磁盘并比对打开时的 SHA-256；不一致就拒绝并在通知里提供 `Reload`，绝不静默覆盖外部修改。
- **编码与权限**：编辑器内部统一用 LF；保存时恢复打开时检测到的行尾（CRLF/LF）和 UTF-8 BOM，保留文件末尾是否有换行，并保留文件权限位。行尾只按第一处换行判断：混合行尾或只有 `\r` 的文件会统一为检测到的类型（通常是 LF）。写入使用同目录临时文件加原子重命名，失败时旧文件保持不变。
- **边界**：只接受仓库内、非 `.git`、非符号链接、非子模块、非二进制、有效 UTF-8、原始文件和编辑后内容都不超过 1 MiB 的普通文件；只读文件在保存时明确报错。
- **工具栏**：编辑模式下保存（⌘S）、还原（Revert，回到最近一次保存或重新加载的内容）、完成（Done，返回只读查看器）；`Edit` 的快捷键是 ⌘E。F4 在工作树文件查看页签上也能打开外部编辑器（此前只在工作区 diff 上；历史版本的文件查看页签仍不提供）。
- **未保存缓冲**：编辑期间状态刷新不重载该页签；保存失败时的 `Reload` 通知在编辑模式内显式丢弃缓冲并读取磁盘，`Done` 退出编辑时也会重新读取。关闭页签、关闭其他/全部页签、切换仓库、打开子模块、移除当前仓库以及关闭窗口/从菜单退出前都会确认；安装更新后的自动重启不经过确认，更新前需自行保存。保存成功后焦点回到编辑器。
- **不做**：补全、跳转定义、引用、符号大纲、多光标、块选择、格式化、自动保存、LSP、冲突结果编辑；diff、历史版本和冲突视图保持只读。

## 代价

- 1 MiB 上限同时约束原始文件和保存后的文本：在接近上限的文件里继续输入可能无法保存，必须先缩短；每次编辑都要重建显示行与语法 span，更大的文件仍交给外部编辑器。
- 混合行尾不保真，保存后统一为第一处换行检测到的类型；只有 `\r` 的旧 Mac 文件会变成 LF。制表符在显示上按四列展开（宽字符占两列），保存的是原始制表符。
- 没有自动保存；崩溃、强制退出或安装更新后的自动重启会丢失未保存缓冲。编辑模式内外部修改只能通过保存失败通知里的 `Reload` 放弃本地缓冲，或点 `Done` 退出后重新读取；不提供三方合并。
- 文件末尾有换行时，光标落在最后一个可见行的行末：在该位置继续输入会在下一行产生内容，点击同一像素则落在行末之前。这是没有虚拟末尾行的取舍，和普通编辑器略有不同。
- 路径校验是词法的：拒绝目标本身是符号链接，但不解析父目录的符号链接。
- 原生文本服务的行为以 macOS 与无头驱动为主；Windows 实机输入法、Linux 输入法与 WSL UNC 路径上的原子重命名仍待实机验收。
- 冲突文件仍只读：用户要继续使用逐块解决或外部编辑器，不能在应用内直接改冲突标记。

## 复审条件

- 需要编辑超过 1 MiB 的文件，或需要保留混合行尾：先做增量显示行与分块加载，并补可重复的输入延迟基准，再调整上限。
- 需要补全、跳转、LSP、多光标或格式化：另立决策，不把本模式扩成 IDE。
- 需要编辑历史版本、diff 或冲突结果：先确定保存目标与 Git 状态协作，再扩大范围。
- 外部修改需要合并而不是放弃：改为显式的三方合并流程，仍然禁止静默覆盖。
- Windows、Linux 或 WSL 实机发现原生输入或原子写在目标平台上不可用：按平台能力降级为外部编辑器入口，并回写本节。
