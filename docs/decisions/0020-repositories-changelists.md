# 0020 多仓库工作区与 ChangeList

- 状态：已采用（2026-11）

## 背景

单仓库窗口需要频繁重新打开项目，也无法把同一仓库中不同目的的改动分组。多仓库总览和本地 ChangeList 可以减少切换成本，但必须让用户清楚每次 Git 操作的仓库和提交范围。

## 决定

- 工作区保存用户显式添加的仓库，不自动扫描目录。以解析符号链接后的工作树根目录去重；同一 Git 仓库的链接工作树各自列出。用户显式触发、从父目录发现子仓库的流程见 [0036](0036-repository-discovery.md)。
- 总览显示各仓库分支及文件状态，切换后再查看目标文件的 Diff。Git 操作仍只作用于当前仓库，不提供跨仓库提交。
- 活动仓库保持文件监听；其他仓库在打开总览或手动刷新时查询。查询失败保留上次成功的状态并显示错误，旧请求不能恢复已经移除的条目。
- Git 写入期间拒绝切换和移除活动仓库。仓库代次持续递增，关闭后重新打开也不复用，避免旧视图和查询误认新仓库。
- 切换仓库保存当前窗口中各仓库的普通提交说明草稿；不恢复 Amend 模式。草稿不持久化到磁盘。
- ChangeList 按仓库根目录保存稳定 ID、名称和文件归属。Default 不可重命名或删除；删除其他清单只将成员归回 Default，不修改文件或索引。
- 筛选仅隐藏不属于清单的未暂存和未跟踪文件。所有已暂存文件与冲突始终可见。筛选时明确显示提交包含全部已暂存内容；批量暂存和分组选择只针对可见文件。
- 元数据分别保存到设置目录的 `workspace.json` 和 `changelists.json`，不写入仓库或 `.git`，不改变原设置格式。

## 边界

ChangeList 是文件组织方式，不是多个独立索引，也不支持按清单拆分同一文件中的不同修改。已提交变干净的路径保留归属，后续修改仍回到原清单。Git 检测到的重命名迁移归属，无法检测的删除后新建不能保证跟随。

非活动仓库状态不是实时监听结果。移除仓库只移除工作区条目，磁盘内容保持原样。跨进程同时修改设置目录的协调、大规模仓库性能及其他桌面平台仍需要单独验证。

## 验证

真实临时仓库覆盖切换、同名文件隔离、工作树去重、写入保护、持久化和清单归属；Viva headless 覆盖总览、筛选、分组暂存与提交范围提示，截图记录关键状态，不打开应用窗口。
