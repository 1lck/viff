# 0048 复用 Git 状态并缓存 LFS 属性文件发现

- 状态：已采用（2026-11）
- 部分替代：[0031](0031-lfs.md) 和 [0047](0047-lfs-on-demand-statistics.md) 的规则发现与失效条件。

## 背景

LFS 文件统计改为按需之后，自动规则检测仍通过一次带 `--others` 的 `ls-files` 寻找嵌套属性文件。大型工作树中，这与常规 `status --untracked-files=all` 重复遍历。[性能 #3](https://github.com/muchenhen/viff/issues/3) 单独解决这部分成本。

## 替代项

- 延长发现间隔：仍会重复遍历，还会延迟检测嵌套属性文件的新增和删除。
- 只监听 `.gitattributes` 路径：无法覆盖忽略规则影响、监听溢出、SSH，以及当前只提供粗粒度轮询的系统。
- 直接读取并解析 Git 索引：需要兼容分离索引、稀疏索引和不同对象格式；继续由 Git 解释索引。

## 决定

- 状态先发布，后台检测使用同一份完整 porcelain v2 状态。可见的未跟踪嵌套属性来自状态的原始 NUL 路径；忽略规则改变后，下一份状态自然替换候选。根属性文件始终检查。
- 首次及工作树的索引变化时，通过 `git ls-files -z --cached -- ':(glob)**/.gitattributes'` 更新已跟踪候选。枚举前后核对 Git 实际索引文件的身份、大小和时间，防止外部索引替换污染缓存；也能发现被 porcelain 隐藏的 intent-to-add 条目。索引不变时复用候选，没有定时到期枚举。
- 每份完成的状态触发一次后台检查。只读取当前候选，逐文件核对内容摘要，复用未变化的解析结果。保持每文件 1 MiB、最多展示 512 条模式；解析缓存最多保留 512 个条目、512 条模式和 4 MiB 的路径及模式文本。缓存随实际工作树关闭、切换或重新打开而释放。
- 手动刷新、监听溢出和状态失败使发现缓存失效。等待下一份完整状态，再执行一次只查索引的发现。较早一代的结果丢弃；并发刷新只保留最新一次待检查输入。
- 发现、读取失败或取消时保留最后成功的规则，LFS 提示显示错误码。相同输入的失败至少间隔五秒，等待下一次状态更新；用户手动刷新可立即重试。Git LFS 能力和主动文件统计沿用原有行为。

## 代价与边界

- 读取已知文件内容有固定成本，可识别大小与修改时间均未改变的替换。SSH 通过既有只读传输检查索引元数据并读取候选；WSL 通过其文件系统路径读取。缓存不会保留原始文件内容。完整属性语义、`.git/info/attributes` 与受管文件统计的范围沿用前两个决策。
- 状态提供当时可见的未跟踪路径，索引候选单独与其来源关联。外部写入恰好落在两次读取之间时，下一次状态更新会重新核对。
- Windows 工作树的检查仍跟随现有状态轮询；原生 Windows 监听由[性能 #4](https://github.com/muchenhen/viff/issues/4)跟进。

## 复审条件

- 大量属性文件导致读取、摘要或 SSH 往返成为明显瓶颈时，评估批量读取或利用可靠的路径事件进一步缩小检查范围。
- 如果 Git 改变 porcelain 状态或稀疏索引的候选语义，重查未跟踪与索引发现的对应关系。

## 验证

隔离仓库覆盖五分钟等效刷新、根和嵌套候选变化、同长度同时间戳替换、忽略、暂存/取消暂存、重命名、工作树隔离和失败恢复。性能记录见[测试说明](../testing.md)。
