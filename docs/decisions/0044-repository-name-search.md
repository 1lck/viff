# 0044 欢迎页仓库搜索默认只匹配名称

- 状态：已采用（2026-11）
- 相关：欢迎页 `Search projects`、[0041](0041-commit-time-and-clock-format.md)、[0043](0043-remote-ssh-readonly.md)
- 触及领域：`internal/ui`、`internal/i18n`

## 背景

0041 让欢迎页搜索同时覆盖最近项目与工作区仓库，解决「最近列表装不下一百多个仓库」的问题。当时的实现把查询词与整个仓库路径做子序列匹配（`fuzzy`），因此路径里任何一段都可能命中：

- 用户反馈：他的代码仓库都在同一个父目录下（例如 `.../ips/`），仓库名是缩写；搜索 `ips` 想找名字里带这个缩写的仓库，结果列表里出现了 94 个候选仓库——父目录 `ips` 命中了目录下的每一个仓库。
- 名称本身是缩写时，子序列匹配也会放宽命中：`ips` 可以分别落在名称的首字母里，而不是一段连续名称。

对「按名字找一个已知项目」这个主要场景，整条路径参与匹配既没有体现在界面上，也无法关闭，用户只能靠结果数量判断匹配范围。

## 替代项

1. **保持整条路径匹配**：实现最简单，但用户无法表达「我只想按名字找」，94 个候选的问题会复现；否决。
2. **只按名称匹配，删除路径匹配**：解决了反馈，但「列出某个父目录下的全部仓库」是真实需求（例如迁移、批量导入前的确认）；否决。
3. **同名优先排序，仍列出所有路径命中**：结果数量没有减少，只是顺序变了；用户仍然要从 94 行里挑，且「为什么它会出现在这里」依旧不可见；否决。
4. **名称默认 + 可切换的完整路径范围**（采纳）：默认行为符合「搜索 = 按名字找项目」，保留路径搜索作为显式选择。

## 决定

- 欢迎页搜索框新增范围控件（搜索框右端、与输入区共用边框）：显示当前范围 `Name` 或 `Path`，点击或聚焦后按 Enter 打开同一个两项菜单，Tab 可到达，Esc 关闭。
- **`Name` 是默认值**：查询词与行上显示的仓库短名（`repoRootName`，SSH 仓库保留 `user@host` 身份）做大小写不敏感的子串匹配，不把父目录纳入。
- **`Path` 保留原行为**：查询词与完整路径做大小写不敏感的子序列匹配（`fuzzy`），用于按父目录或路径片段筛选。
- 空查询语义不变：仍只显示最近项目；输入查询后才并入工作区仓库。
- 范围是窗口内的会话状态，不写入设置：每次启动回到 `Name`，与「搜索框是临时入口」的定位一致。
- 新文案走 `internal/i18n`（`welcome.search.*`），英文默认、简体中文同步。
- 匹配规则抽成 `projectMatches(root, q, scope)`，供列表与无头测试共用，避免界面与测试各写一套判断。
- 最小窗口（900×600）下五个工具栏按钮只剩 80 点的搜索框；此时搜索框连同范围控件换到按钮下一行，而不是把查询裁成一个字母。正常宽度仍保持按钮与搜索同排。

## 代价

- 依赖路径搜索的用户升级后第一次搜索会少看到结果，需要多点一次范围菜单；这是本次有意的默认值变化。
- 名称匹配是子串，不做子序列/拼写近似：记住的是首字母缩写（例如用 `vr` 找 `viff-repo`）时 `Name` 不会命中，需切到 `Path` 或输入更完整的名称。
- 搜索框内多了一个控件。窗口最小宽度 900 时搜索行下移约 40 点，最近项目少显示不到一行；换行阈值是 240 点，低于它的宽度没有更细的折叠方案。
- 两套匹配语义（子串与子序列）需要分别测试；范围切换后选中行会重置，避免选中项指向新列表之外的行。

## 复审条件

- 若反馈集中在「每次启动都要重新选 Path」：把范围持久化进 `storage.Settings`，并写迁移与默认值测试，而不是改变默认值。
- 若 `Path` 仍经常返回大量无关键结果：在路径范围内增加前缀/最近使用优先的排序，或提供第三种「仅父目录」范围；不要退回全局子序列匹配。
- 若用户需要跨仓库搜索文件内容：这是 [0037](0037-content-search.md) 复审条件里的另一件事，按新 ADR 设计范围、索引与上限，不并入本控件。
- 若名称搜索仍被要求支持缩写/拼写近似：新增独立于 `Name`/`Path` 的模糊名称模式，保留当前可预测的子串默认值。
