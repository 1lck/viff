# 0034 记住窗口位置

- 状态：已采用（2026-11）

## 背景

Viff 之前只保存窗口尺寸（`Settings.Window.Width`/`Height`），位置完全交给系统。在 macOS 多显示器上这表现为：窗口每次都在主屏打开，拖到副屏、关掉、再启动又要拖一次。尺寸能记住而位置记不住，说明缺的是位置这一半，不是平台差异。

Viva v0.2.4 已经提供两个正好够用的入口（已核实模块源码）：`app.Config.Origin *ui.Point` 是内容区左上角的屏幕坐标，`app.Config.OnFrameChange func(ui.Rect)` 在内容区移动或缩放时回调。macOS 的 `placeAtOrigin` 会把落点算到窗口中点所在的屏幕，落点命中不了任何屏幕时回退主屏，并把窗口夹进可见区域。

## 替代项

- **自己枚举显示器并校验保存的矩形**：Viff 没有屏幕枚举 API，得新增平台代码；而 Viva 已经做了“命中不了就回退主屏”，重复实现只会多一张可能过时的屏幕表。
- **只记住上次所用的显示器编号**：显示器排列与编号会变，镜像模式下编号没有稳定含义。
- **每次启动都居中**：比压在角落里好，但仍不尊重用户的选择，跨屏场景没有解决。
- **用坐标是否非零推断“保存过位置”**：`(0,0)` 是主屏左上角的真实位置，会被误判成未保存。

## 决定

- `Settings.Window` 增加 `X`/`Y`（屏幕坐标，副屏在主屏左侧或上方时为负）与 `Positioned`。`Positioned` 单独记录是否保存过位置，因为 `(0,0)` 合法，不能当哨兵值。
- 启动时 `Positioned` 为真就把 `X`/`Y` 交给 `Config.Origin`；为假则完全不设 `Origin`，由系统决定落点。
- 运行期 `Config.OnFrameChange` 写回位置并走 `saveSettings()`（600ms 去抖：一次拖动会上报每个中间位置，不能一次一写）。尺寸仍然只由 `OnResize` 记录。
- 旧设置文件没有这些字段，`Positioned` 默认为假，行为与升级前一致。`sanitize` 在尺寸非法而回落默认几何时会一并丢掉位置，避免恢复一个与默认尺寸不符的角点。

## 代价

- 拖动窗口会触发设置写入（去抖后一次），与其他设置共用同一个 `time.AfterFunc` 定时器；拖动过程中后一次写入会替换前一次，最终位置仍然正确。
- macOS 上最大化或缩放后的 frame 也会被记录，下次按记录的角点加上一次的正常尺寸打开。与多数桌面应用一致，不额外区分最大化状态。
- 位置有效性依赖 Viva 的屏幕回退。将来 Viva 改掉这个行为，就得在 `internal/platform` 里自己校验。
- 无头测试只能断言设置字段与 `Config.Origin`；真实多显示器落位需要在桌面上人工验收。

## 复审条件

- Viva 改变或移除 `Origin`/`OnFrameChange` 的语义（例如不再回退主屏）时，在这里补 `internal/platform` 的屏幕校验。
- 用户反馈多显示器下仍落到错误的屏幕，或拔掉外接屏后窗口不可见时，改为保存显示器标识而不是裸坐标。
- 需要记住最大化/全屏状态时另立设计：要给 `Window` 增加显式状态字段，不能从尺寸或坐标推断。
