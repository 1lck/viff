# 0047 按需查询 LFS 文件统计

- 状态：已采用（2026-11）；规则发现与缓存边界由 [0048](0048-lfs-attribute-discovery-cache.md) 更新，以下保留原决策背景。
- 部分替代：[0031](0031-lfs.md) 的自动文件枚举、统计生命周期与状态栏数量语义；保留原决策背景。

## 背景

大型 UE 仓库中的完整 LFS 枚举比普通状态查询耗时高，并推迟改动列表出现。[性能 #2](https://github.com/muchenhen/viff/issues/2) 达到 ADR 0031 原有的复审条件。规则、工具能力与精确文件统计的刷新频率应分别确定。

## 替代项

- 继续随普通刷新枚举：状态快照必须等昂贵查询结束，空闲时也持续扫描。
- 只延长枚举间隔：降低频率，却仍有自动开销和首次打开的延迟。
- 后台自动预取：不阻塞状态，但用户未查询时仍需支付完整扫描成本。

## 决定

- 自动检测工具能力和根/嵌套属性规则，保留原有缓存和发现范围。状态、操作与冲突先作为一致快照发布，规则检测独立更新快照。未找到规则时，是否还有已提交的 LFS 指针需主动统计。
- 只有显式 **Refresh LFS Statistics / 更新 LFS 统计** 才执行 `git lfs ls-files --name-only -z`，保留 NUL 路径；不支持 -z 的版本改用 JSON，以正确统计含换行的路径。首次打开、普通文件变化、写操作结束和一般刷新不枚举。
- 同一工作树只有一个在途文件统计，重复请求合并；关闭或切换取消旧查询，在实际退出前保留该工作树的名额，重开时不重用旧结果。不同工作树使用独立状态。
- 查询绑定仓库代次、请求及相关状态代次。HEAD/当前分支或暂存内容变化使统计过期；查询前后再读取 HEAD 与暂存差异，捕获普通刷新之间的外部修改。过期不会自动枚举，失败保留上次成功结果和时间。
- 已发现规则时状态栏显示 `LFS`。点击标记、Tab 聚焦后按 Enter，或使用 Git 工具窗口菜单主动统计；无规则时仍可从菜单查询。区分未查询、加载中、有效（含零）、过期、失败。提示显示上次成功时间，菜单可复制有效的完整文件清单。
- 缺依赖提示、安装命令复制与只检测不管理的边界沿用 0031。
- `repo.lfs` 只记录状态、计数、耗时、错误码；枚举的路径、原始输出和错误详情不写日志或 Console。

## 代价与边界

- 根属性指纹与 30 秒/元数据触发的规则发现仍会执行 `git ls-files`，包括查找未跟踪属性文件。这部分成本按[性能 #3](https://github.com/muchenhen/viff/issues/3)另行评估。
- 文件统计只反映上次显式查询。HEAD/index 改变时保留数字并标记过期；用户决定何时重新扫描。
- 显式统计前后增加 HEAD 与暂存差异校验；每次普通状态解析同时计算暂存对象身份，捕获同一路径反复暂存而状态字母不变的情况。
- 原生 Windows 使用 Job Object 回收进程树；Unix 使用独立进程组。SSH/WSL 的统计使用一次性的标准输入保活与远端 shell guard，在另一侧停止并回收后代，再返回退出确认。若传输中断而未收到确认，工作树统计入口保持禁用，并显示 `lfs.cleanup_unconfirmed`；检查仓库机器上的 Git/LFS 进程后重启 Viff 才可重试。规则检测继续沿用既有传输取消机制。
- Git LFS 旧版本拒绝 `-z` 时要求支持 `ls-files --json`（包括实测的 3.5.1）；两种机器格式都不可用时报告失败，不用含糊的换行记录替代精确统计。规则读取错误保留部分成功结果；缺依赖的负缓存仍按进程维护。

## 复审条件

- 属性发现仍占明显 CPU 时，按 #3 复审目录遍历与规则缓存。
- 若需要下载、跟踪或管理 LFS 对象，另立决策评估凭据和存储边界。
- Git LFS 的 NUL/JSON 格式变化或不支持两者的版本成为实际需求时，复审机器格式兼容策略。

## 验证

隔离临时仓库测试覆盖自动刷新零枚举、状态独立更新、重复点击、成功零值、失败保留结果、外部暂存变化、HEAD 变化、关闭/切换/重开。Windows 进程测试检查取消后的后代进程退出；无头 UI 测试覆盖明暗主题、键盘统计、计数、复制清单与缺依赖提示。性能方法与结果见 [测试说明](../testing.md)。
