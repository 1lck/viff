# 0046 多仓库项目的 Project 面板聚合（Phase A）

- 状态：已采用（2026-11）

## 背景

用户经常把多个独立 Git 仓库放在同一个父目录下，例如 `workspace/project-a`、`workspace/project-b`。Viff 已经有显式工作区列表、Repositories 总览，以及从父目录发现并批量导入仓库的流程（[0020](0020-repositories-changelists.md)、[0036](0036-repository-discovery.md)），但 Project 面板只显示当前活动仓库，同级仓库只能在 Repositories 对话框里看到。Issue [#81](https://github.com/1lck/viff/issues/81) 要求像 IntelliJ IDEA 一样，在项目树里看见父目录下的多个 Git 项目；截图还展示了跨仓库选择并 Push Commits 的场景。

跨仓库提交与推送需要每个仓库独立的会话状态：`RepoState`、文件监听、写锁、提交说明草稿、日志与视图代次都要按仓库分别维护。那会改动 `Workspace` 的单活动仓库模型，也会改变“同一时间只有一个仓库执行写操作”的既有边界（0020），不适合作为本 issue 的第一步。

因此本决策只交付 Phase A：把显式导入的仓库在 Project 面板里按工作区聚合展示，并提供切换入口；跨仓库 commit/push 暂缓。

## 替代项

- **每个仓库开一个窗口。** 不需要改 `Workspace`，但无法在一个项目树里总览多个仓库，窗口、监听和内存随仓库数量线性增加，也不符合 Issue #81 的 IntelliJ 项目视图预期。
- **启动或打开父目录时自动扫描并导入。** 违反 0020 的“工作区只保存用户显式添加的仓库”，也让打开目录的成本不可预期；0036 已经用显式发现对话框解决这个入口，不采用。
- **把 Repositories 总览直接当成项目树。** 总览是模态对话框，适合批量查看分支和改动，但不能持续停在左侧与文件树、日志并排；把对话框改成常驻面板会引入另一套导航状态，不采用。
- **为所有非活动仓库加载完整文件树。** 每个仓库一次 `ls-files` 会放大打开面板和刷新成本，也违反 0020 的“非活动仓库只保留导航摘要”，不采用。
- **本轮直接实现跨仓库 commit/push。** 需要 per-repo session 与跨会话写队列，超出 Phase A；在没有单独设计前实现，会把单活动仓库的代次、监听和写保护拆坏，不采用。

## 决定

- 工作区里有多个仓库时，Project 面板在活动仓库文件树之上增加一个 **Workspace** 根节点，按 `Workspace.Repositories` 的顺序列出所有显式导入的仓库。只有一个仓库时保持原有布局：仓库本身就是根节点，不额外套一层。
- 每个仓库行显示仓库名和摘要。活动仓库从当前 `RepoState` 读取分支与改动计数；非活动仓库使用工作区列表里最近一次成功查询的缓存，显示分支与改动计数、错误，或“打开后加载状态”。
- 活动仓库行继续承载现有的文件树，折叠/展开、过滤、工具栏、右键菜单与文件打开行为不变。非活动仓库行是叶子节点，不显示子目录或文件；它只有仓库节点和摘要。
- 点击非活动仓库行走现有 `switchRepository`：先完成原有的脏缓冲确认，再通过 `ActivateRepository` 切换；切换后仍只有一个活动 `RepoState`、一个监听和一个写操作边界。活动仓库行点击折叠/展开文件树。键盘的 Enter、Space、Right 对非活动行执行同样的切换。
- Project 面板不新增 app 接口，也不修改 `Workspace` 的单 `RepoState` 架构。面板每次重画从 `Workspace.Repositories` 派生行，仓库列表或活动根变化时才重建；不并发请求非活动仓库的文件树，也不在打开面板时轮询所有仓库。
- 非活动仓库的摘要由激活该仓库或打开 Repositories 总览时的显式刷新更新；面板本身不启动后台状态查询。
- 不提供跨仓库暂存、提交、推送或其他写操作，也不把多个仓库合并成一个 Git 仓库。ChangeList、写锁与提交范围仍属于活动仓库。

## 代价

- 非活动行的摘要是缓存：仓库被外部工具改动后，Project 面板不会自动更新它，直到该仓库被激活或用户打开 Repositories 总览刷新。首次见到一个未加载的仓库时，行内只能显示“打开后加载状态”。
- Project 面板仍是单仓库文件树：不能同时展开两个仓库的文件，不能跨仓库查看 diff，也不能在一个动作里提交多个仓库。
- 仓库分行由 UI 从工作区列表派生，`app` 不知道“项目分组”这个概念；将来若引入 per-repo session 或用户自定义分组，需要替换这一层行模型。
- Issue #81 截图里的跨仓库 Push Commits 仍未实现；本次只解决“在 Project 面板看见并切换多个仓库”。

## 复审条件

- Issue #81 或用户明确要求跨仓库 commit/push、同时展开多个仓库的文件树或按仓库分别保留页签时，先设计 per-repo session，并重新评估 [0020](0020-repositories-changelists.md) 的单活动仓库写模型。
- 工作区仓库数量增大到打开 Project 面板可感知变慢（用真实工作区测量派生行与摘要查询），需要虚拟化、显式刷新按钮或缩短摘要缓存生命周期。
- 用户期望非活动仓库的状态实时更新时，先决定监听/轮询策略与成本，再扩展 0020 的非活动仓库刷新边界。
- 用户需要按父目录或自定义项目分组，而不是一个平铺的 Workspace 列表时，再引入持久化的项目分组元数据。
