# 0040 双击分支默认只筛选，不检出

- 状态：已采用（2026-11）

## 背景

日志左侧分支树里，双击一行本地分支会直接检出该分支（`internal/ui/gitwin.go` 的行双击回调直接调用 `Checkout`）。工作区有未提交改动时，Git 拒绝检出，界面再弹出 Smart Checkout 的确认框，问是否连同未跟踪文件一起 stash。

这条路径有两个问题：

- **代价与手感不匹配**。单击已经完成「选中这行 + 用该分支筛选日志」，双击在它之上再写一次工作区，很容易变成误触；用户要的往往只是「只看这个分支」。
- **没有退路**。反馈（#50）里明确写着找不到关掉这个行为的地方：不想让双击改工作区的人，只能改成不去双击分支行，而右键菜单里的 Checkout 才是显式入口。

## 替代项

1. **保持现状**：双击检出，右键也能检出。代价是误触照旧，且用户无法关掉。
2. **干脆去掉双击检出**：只留右键菜单。代价是把「双击即检出」当成习惯的人失去快捷方式，而 IntelliJ 系客户端都保留了这个手势。
3. **做成设置项，默认关闭**（采纳）：默认行为与「只筛选」一致，需要的人一次性打开。

## 决定

- 新增持久化设置 `checkoutOnDoubleClick`（设置 → General → 行为「双击分支时检出该分支」），默认 `false`；旧设置文件没有该字段，`Load` 反序列化进 `Defaults()`，因此升级不会把旧行为重新打开。
- 关闭时双击只保留单击已有的效果：选中该行、把日志筛选到该分支、不调用任何写操作，也不弹出任何对话框。
- 打开时双击复用右键 Checkout 的同一个入口 `checkoutBranch`，因此「分支已被其他工作树检出」时打开那个工作树，而不是报检出失败。
- 检出的保护不变：工作区有未提交改动时仍由 Smart Checkout 确认，不自动 stash、不丢弃改动；取消后分支与工作区保持原样。
- 右键菜单的 Checkout 与弹窗路径都不受该设置影响。
- 「在文件管理器中显示」这类文案随平台命名（macOS 用 Finder、Windows 用 File Explorer、其余用文件管理器），与本次改动一起交付；它只影响文案，不涉及行为，因此不单独立一条 ADR。

## 代价

- 设置里多一个只有一项的分组（行为），设置页因此比原来高一行人高；正文在窗口不够高时靠滚动，未做进一步压缩。
- 默认关闭意味着从 IntelliJ 转来的用户第一次双击不会检出，需要自己发现并打开该设置；提示只写在设置页的说明行里，没有做「双击时提示一次」这类一次性引导。
- 保留了两个入口（双击与右键），两处行为一致性靠共用 `checkoutBranch` 维持；以后增加第三种检出方式时必须同样走它，否则会绕开工作树判断。

## 复审条件

- 若出现「双击分支没有反应，以为是坏了」的集中反馈，考虑在首次双击未检出时给一次可关闭的提示，或把默认值改成跟随上次选择。
- 若设置项反馈过多（用户找不到开关），把该开关移到分支面板的右键菜单里，与本行行为就近摆放。
- 若将来引入「双击分行可配置」的通用机制（多个双击手势共用一个设置页），把这一项并入该机制，不再为单个手势保留独立字段。
