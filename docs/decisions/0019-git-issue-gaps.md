# 0019 Git issue 对照后的功能补齐

- 状态：已采用（2026-11）
- 部分替代：[0005](0005-read-only-conflicts.md)、[0010](0010-submodule-status.md)

## 背景

对照 Lithe-IDEA 的 Git issues 并在 Viva 无头界面复测，发现多提交选择没有文件汇总、长提交说明被截断、控制台长行不可横向查看。另有两项原先明确留给外部工具的操作：逐块解决文本冲突，以及添加、移除和停用子模块。

## 决定

- 多选提交显示各提交相对第一父提交的受影响文件并集，根提交相对空树比较。按路径去重并保留来源；一个文件涉及多个提交时，选择来源后查看该提交的真实 diff。已有两提交净差异比较继续保留。
- 查询在后台执行，改变选择时取消旧查询，并拒绝陈旧结果。部分查询失败需要明确标识，不能当作完整汇总。
- 提交说明保留全部文本，按面板宽度缓存换行布局，滚动时只画可见行；切换提交时回到顶部。
- 控制台保留不折行的输出，通过横向滚动查看长行；清空时重置偏移，用户向上阅读时不强制跟随新输出。
- 文本冲突可逐块接受 Ours、Theirs 或 Both。Both 按 Ours、Theirs 的顺序保留内容，不加入 diff3 的 base 段。写入前重新检查未合并状态与磁盘内容，拒绝陈旧视图；不自动暂存，仍由用户执行 Mark as Resolved。
- 子模块对话框支持添加、移除和 deinit。移除与 deinit 只对当前仓库直接管理的子模块提供；嵌套子模块需打开所属仓库后管理。脏内容需明确确认强制操作，不默认开启 file 协议。

## 代价与边界

多提交汇总仍需查询多个提交，大选择可能有等待。冲突处理不是自由文本编辑器，也不提供一次接受所有块；最后一次内容检查与文件替换之间仍存在外部编辑竞态。二进制、过大文件和不可靠标记继续交给外部编辑器。

子模块移除保留 Git 自身的模块对象库，不把它当作磁盘清理功能。多个仓库统一视图、多个 ChangeList 和结构化表格 Diff 不属于此次变更。

## 验证

真实临时仓库测试覆盖文件并集、删除与重命名、陈旧结果、冲突块与换行保留、外部编辑保护、子模块路径及脏内容拒绝。Viva headless 用例检查界面交互与截图，不打开应用窗口。
