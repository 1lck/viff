# 0024 只读文件浏览：Project 工具窗口与 Quick Open

- 状态：已采用（2026-11）

## 背景

0007 给了单版本只读查看器和 blame，0017 能从 Log 浏览某个提交的仓库树，但工作树本身没有入口：想看一个没有改动、也不在提交里的文件，只能去终端或外部编辑器。设计稿把「文件查看」列为 P1，但此前只覆盖了「指定版本内容」，没有决策过工作树的浏览入口。

用户需要的不是 IDE：不编辑、不做语言服务、不建全项目索引，只要能按目录找到文件、只读打开、用 Git 状态着色，并保持 Git 是事实来源。

## 替代项

- **放进 Commit 工具的第三个页签**：实现最省，但文件浏览会被埋在提交流程里，没有项目根节点、独立工具栏和面板宽度；实际试用后确认这不是目标形态。
- **只做 Quick Open**：键盘可达，但看不到仓库结构，没有目录折叠、状态颜色与右键动作。
- **每次展开目录跑一次 Git**：命令数量随交互增长，刷新要处理更多代次；工作树文件本来可以一次列出。
- **直接读磁盘目录**：会把构建产物、ignored 文件和 `.git` 带进来，与 Git 的索引视图不一致；`ls-files` 的「索引 + 未跟踪」才与 Git 状态一致。
- **复用提交树浏览器做成工作树版本**：那是弹窗，关闭即失去浏览上下文，不适合反复查看。

## 决定

- 左侧 stripe 增加 **Project** 工具窗口（⌘1），与 Commit 共用左侧停靠区：一次显示一个（⌘0 切回 Commit），避免两个固定面板挤压编辑器；宽度 `ProjectPanelWidth` 持久化。默认仍显示 Commit 面板，Project 由 ⌘1 或文件夹图标打开。
- 面板有项目根节点（仓库名 + 缩短后的绝对路径）、标题与工具条（Refresh、Collapse All、Expand All、Open File、Hide）以及过滤框；根节点可折叠整棵树。
- 列表来自一次 `git ls-files -z --cached --others --exclude-standard`：索引文件加未跟踪文件，排除 ignored；NUL 分段、路径原样保留、在 Go 内去重并排序（未合并索引可能重复同一路径）。
- 目录层级在界面内由路径派生：`rebuild` 时只建目录节点，绘制只处理可见行；折叠状态按路径记录，过滤激活时自动展开并只保留匹配项。这样十万级路径不会为每个文件创建 UI 节点。
- 打开沿用 0007 的 `DiffSource.View`：工作树版本只读查看；单击进预览页签，双击固定，与变更列表一致，不维护第二套渲染器。
- 名称按 `RepoState.Status` 着色（冲突、未跟踪、新增、修改、删除等）；`StatusTime` 前进时重新列目录，外部 AI、编辑器或终端改文件后界面自动跟上。
- **Quick Open（⇧⌘O）** 用同一份列表做大小写不敏感的子串过滤，打开仍走同一个查看器；不新增缓存。
- **只读查看器支持文本选择与复制**：鼠标拖选、双击选词、Shift+方向键扩展、⌘A 全选、⌘C 复制；坐标按显示单元格映射，UTF-8 与宽字符按整字符取整。选择在重新加载、切换/关闭页签和切换仓库时清空，避免索引已变化的文本。
- 右键菜单只给只读动作：Open、Open in External Editor、Annotate with Git Blame、Show History、Copy Path / Relative Path、Show in Finder。
- 面板按 IntelliJ 的 Project 视图组织：根节点、目录优先、状态着色、单击预览/双击固定；折叠状态按路径记录，过滤时自动展开。
- 明确不做：编辑、补全、跳转定义、引用、符号大纲、全项目搜索。与 `docs/design.md` 的边界一致。

## 代价

- Project 与 Commit 共用左侧停靠区：不能同时看到两者；需要边看文件边提交时要来回切换（后续可加并排停靠）。默认显示 Commit，Project 需要 ⌘1 打开。
- ignored 文件默认不显示，也没有开关；十万级路径全量放在内存里，尚未测量。
- 目录折叠状态不持久化；过滤是子串匹配，不是通配符或路径段语法。
- Project 中打开的图片仍只显示二进制说明（diff 的图片预览不适用于单版本查看）；超大文件仍是 8 MiB 上限后转外部打开。
- 选择按显示文本复制：制表符展开成空格，不保留原始制表符；没有块选择、多光标或语法感知复制。
- 拖选到可视区边缘时不会自动滚动，超出视口的内容需要先滚动再选。
- 在 Project 中单击文件会立即加载预览 diff，和变更列表的行为一致，但大文件上会有一次可见等待。

## 复审条件

- 需要 Project 与 Commit 并排停靠、Project 默认打开，或把左侧停靠区扩成可拆分的多面板时，重新评估布局与焦点。
- 需要 ignored 开关、折叠状态持久化、通配符过滤、图片预览或在树内直接看 diff 时扩展这次决定。
- 十万级路径的内存占用或打开延迟超出预算时，改为按目录懒加载，并先补可重复的基准。
