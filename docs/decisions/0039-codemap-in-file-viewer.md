# 0039 代码缩略图只属于只读文件查看器

- 状态：已采用（2026-11）

## 背景

变更刻度（[0007](0007-read-only-file-view.md) 之后的 diff 右缘窄带）之后，diff 右缘又加过一版「代码缩略图」：与刻度共用同一列，把整份文件按语法压成窄条。实际使用暴露两个问题：

- **一列承担两件事**：刻度要标出改动段落，缩略图要显示代码形状，两者叠在同一列上互相削弱；diff 的主要工作是看改动，缩略图在这里几乎不提供额外信息。
- **形态不对**：缩略图与滚动条并排时列宽被压缩，字符单元落到 4pt 以上，字形糊成色块；短文件还会被遮罩整块盖住，只看得到一层半透明。

同时，只读文件查看器（阅读整份文件的地方）右侧只有一条滚动条，那里才是缩略图真正有用的位置。

## 替代项

1. **保持现状**：diff 与文件查看器共用一列，靠开关切换显示。代价是两种用途继续互相削弱，且列宽在 diff 里更紧张。
2. **两处都画缩略图**：各自独立实现。代价是同一份压缩逻辑出现两条绘制路径，列宽、遮罩与滚动同步要维护两遍。
3. **只放到文件查看器**（采纳）：diff 只保留变更刻度，缩略图成为文件查看器的专属列。

## 决定

- 缩略图只在只读文件查看器绘制，布局为 `[代码区] | [缩略图 72px] | [独立滚动条 12px]`；diff 右缘继续只有变更刻度，由 [0007](0007-read-only-file-view.md) 的刻度列承担滚动条职责。
- 缩略图按**位图**栅格化后作为纹理绘制，而不是每帧用矢量重画：字符单元 2pt、前导留白 3pt，字符列数由上一步的宽度算出，超出部分截断。
- 视口遮罩（框出当前可视范围）与遮罩本身画在更高的合成层（`Canvas.PushLayer`），因为 Viva 在同一层内先合成矩形、后合成位图与文字：不提升图层，遮罩与左侧分隔线都会被纹理盖掉。
- 遮罩的位置与高度与滚动条滑块使用**同一套换算**，两者都读写同一个滚动偏移，因此拖动遮罩时正文、遮罩、滑块自然同步。
- 开关同时存在于文件查看器工具栏与设置 → General；diff 工具栏上不再有开关，因为那里改了设置也看不到变化。
- 缩略图沿用「纯鼠标控件」的既有约定（与变更刻度、覆盖式滚动条一致），键盘的等价操作是 Home/End/PageUp/PageDown 与行滚动；无障碍名称与提示随语言切换。

## 代价

- 每个打开过缩略图的页签各保留一份位图（宽度约 72px，高度按面板高度向上取整到 16px 的档位），长文件不增加位图大小，但文件很多时是常驻内存；本轮不做跨页签共享或卸载。
- 高度按档位量化，渲染时会有不超过 16px 的拉伸，换来拖动窗口边缘时不必每帧重建位图。
- 位图以 1 像素 = 1 点为前提；高 DPI 下纹理由渲染后端放大，字形的锐度取决于后端缩放质量，本轮没有按设备像素栅格化。
- 缩略图的列宽固定，比 diff 右缘的刻度列宽，窗口很窄时正文会先变窄；没有做「窄窗口自动隐藏缩略图」。
- 遮罩使用滚动条与焦点 token，深浅主题下都可见，但短文件（内容不满一屏）时遮罩铺满整列，仍会盖住代码形状。

## 复审条件

- 出现「高 DPI 下缩略图明显发虚」的反馈时，改为按设备像素栅格化，并把像素缩放写进位图缓存键。
- 页签数量多导致常驻内存被测量出来（需给出平台与命令）时，改为只保留当前页签的位图。
- 窗口变窄时正文被压到不可用，则加入按宽度自动收起缩略图，或让用户拖动列宽。
- 若 Viva 提供「同一层内矩形画在图像之上」的显式顺序保证，可以去掉提升图层这一步。
