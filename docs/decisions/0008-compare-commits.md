# 0008 提交比较视图

- 状态：已采用（2026-11）

## 背景
Log 里原本只能把一个提交和工作树比较；分支弹窗的“比较”只过滤出对方多出的提交，看不到文件级差异。排查“这两个提交/tip 之间改了什么”需要一个文件列表。

## 决定
- 任意两个提交都能比较：用 `git diff --name-status -M A B` 列出文件，A 是旧侧、B 是新侧，顺序决定增删方向；不要求 A 是 B 的父提交。
- 打开文件时复用 `DiffSource{Commit: B, Parent: A, Path: p}`。`revisions` 只把两侧读成 `A:p` 和 `B:p`，所以非父子提交也能显示正确的旧/新内容和标题。
- 比较视图是一个模态对话框：顶部显示 `A → B` 与文件数，中间是可滚动的文件列表（状态字母、路径、重命名来源），双击文件或按 Open Diff 在编辑器中打开 diff 页签。
- 分支弹窗保留原有“Compare with …”的 Log 过滤，另加“Show Changed Files”，用两个分支的 tip 打开同一个视图。

## 代价
- 对话框关闭后比较结果不保留，也不支持把比较结果当作一个整体继续操作（暂存、导出补丁）。
- 只有平铺文件列表，没有目录树或多选批量打开。

## 复审条件
需要长期保留比较结果、跨文件批量操作或目录级比较时，改成 Git 工具窗口里的页签。
