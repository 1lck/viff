# 0007 只读文件查看与 blame

- 状态：已采用（2026-11）

## 背景
设计稿把“指定版本内容”放在 P1、blame 放在 P3。查看某个提交里的文件和定位某几行是谁改的，是排查问题时的基本动作，两者共用同一套只读渲染。

## 决定
- 文件视图不新开一套渲染器，而是给 diff 页签加一个“单版本”来源（`DiffSource.View`）：左侧为空，右侧是文件内容，工具栏只保留注解、历史和在外部编辑器打开。
- blame 用一次 `git blame --porcelain` 读出全部提交和每行归属，按提交去重；不逐行调用 Git。
- 注解栏显示作者与作者时间，按提交新旧着色（越新越深）。同一提交连续的行只标一次；点击注解定位到 Log 中的该提交。
- 提交不在当前 Log 筛选结果里时，把哈希放进文本筛选并最多重试两次；仍找不到就放弃，不再改写用户的筛选。
- 工作树文件的视图在 Git 状态变化后重新加载内容和注解；历史版本的视图不刷新。

## 代价
- 每次打开注解都重新跑一次 blame，没有跨页签缓存；仓库很大时会有一次明显的等待。
- 注解栏只按行着色，和 IntelliJ 一样不做块级选中。

## 复审条件
大仓库上 blame 的耗时影响操作时，加入按提交的缓存或增量注解；需要用注解做块级操作时再扩展。
