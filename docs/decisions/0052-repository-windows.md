# 0052 仓库独立窗口

- 状态：已采用（2026-11，[issue #98](https://github.com/1lck/viff/issues/98)）

## 背景

[0020](0020-repositories-changelists.md) 和 [0046](0046-multi-repository-projects.md) 定义了多仓库工作区。用户可以在 Project 面板中查看和切换仓库，切换时会重置编辑页签等视图状态。需要同时对照两个仓库或在另一个仓库工作时，用户希望保留原窗口及其编辑进度。

## 替代项

- **在同一窗口切换**。适合快速导航，每次只能展示一个活动仓库。
- **为每个仓库启动一个进程**。进程间需要协调设置、仓库列表和更新，同时会增加应用实例及资源占用。
- **在一个 Viva 应用中打开多个窗口**。独立维护每个窗口的交互状态，共用应用级数据和生命周期。采用。

## 决定

- 项目菜单提供「在新窗口中打开…」，选择目录后才创建窗口。新窗口走现有打开流程，选择父目录时可继续使用 [0036](0036-repository-discovery.md) 的仓库发现功能。常规「打开…」继续在当前窗口打开。
- 各窗口拥有独立的活动仓库、状态查询与监听、命令日志、编辑页签、提交草稿和终端。关闭窗口时释放该窗口资源。同一 Git common dir 的写入继续由现有串行机制协调。
- 已添加仓库、最近项目、ChangeList、AI 规则及偏好设置由应用共享。仓库列表的增删会同步到各窗口，移除其他窗口正在使用的仓库时会提示。每个窗口独立刷新其仓库状态。
- 托盘和更新属于应用。关闭单个窗口只检查本窗口的未保存编辑，从应用菜单退出或确认安装更新时检查所有窗口。下次启动恢复一个窗口，沿用最近项目和启动窗口的几何记录。

## 代价

- 每个窗口各自持有仓库状态、渲染资源和监听器，同时打开的仓库越多，资源占用越高。
- 目录选择入口面向本地文件系统。已添加的远程仓库仍可通过项目菜单在窗口内切换。
- 窗口关闭后结束该窗口的编辑和终端会话。应用重启只恢复一个窗口，不恢复多窗口布局。

## 复审条件

- 用户频繁要求恢复多窗口布局时，评估多显示器几何、会话文件和异常退出的恢复规则。
- 大仓库多开时发现显著重复查询或渲染成本，先测量再评估按仓库共用只读缓存。
- 用户频繁需要直接在新窗口中打开已登记仓库或 SSH 仓库时，评估在最近项目和 Repositories 中加入口。
